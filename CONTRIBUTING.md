# Contributing

## Principles

- Keep all public examples synthetic or explicitly public.
- Never commit employer code, production data, internal URLs, credentials, or confidential architecture.
- Prefer narrowly scoped tools and least-privilege access.
- Add tests for behavior, security boundaries, and failure cases.
- Separate observed evidence from model-generated inference.

## Proposed workflow

1. Open or select an issue with clear acceptance criteria.
2. Document architectural or security implications.
3. Create a focused branch.
4. Add implementation and automated tests.
5. Update relevant documentation.
6. Submit a pull request explaining evidence, trade-offs, and verification.

## Commit style

Use concise conventional prefixes such as `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, and `chore:`.
